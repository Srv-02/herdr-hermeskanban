# Hermes Kanban

A Kanban panel in the right panel column, opened from a `Hermes` pill at the right end of the tab bar. It follows the focused pane: when that pane runs a Hermes agent on a Herdr machine, it shows that instance's Kanban board (Hermes' board `default`), grouped by status and sorted by priority, from memory at once and synced in the background. A click opens a large overlay with the task, its description, activity and runs, where you comment, unblock, assign, move, reprioritize or archive it; `+` creates a task. The pill's dot and toasts tell when a task needs you, fails or finishes, also while the panel is hidden. Every call runs on the Hermes machine itself, through Herdr's `exec(..., { on: machine })`, as `curl` against Hermes' own web app API on `127.0.0.1:9120`; the access key never leaves that machine.

## How it behaves

- **Follow me** (`lib/instances.js`): the focused pane is Hermes when Herdr reports it (`app === "hermes"` or program `hermes`); its machine comes from its space, or from a terminal block's address `devbox/t3`. A pane on this computer or without Hermes shows `No Hermes in this pane`, never the last board. A focused mod (block or mod pane) keeps the last focus, so typing in the search keeps the board. A 3 s timer notices focus changes and keeps the ages fresh.
- **Visible instances:** machines with at least one open space (`spaces()[].machine`), this computer never. Only those are polled, shown, counted and toasted.
- **Instance binding:** every request, action, board and mark carries the machine; task keys are `[machine, id]`. Overlays take their machine from their props and never read the focus; `api.act(task, …)` takes it from the task alone.
- **Polling** (`watcher.js`, `lib/poller.js`): the pill's copy holding shared `hermes-kanban.lease` (renewed every minute, taken after 3 minutes; from ghchecker) runs a pass every 5 s, even while the panel is hidden. Each visible machine is due every `poll_seconds` (default 30): first the stamp (`find … -printf` of `kanban.db` and `kanban.db-wal`: name, nanosecond mtime, size); `/board` only when the stamp changed, a refresh was asked, or 5 minutes passed; after each good board `/diagnostics?severity=warning` for the problems. `/api/status`, `/workflow` and `/orchestration` at the start, after an error and every 5 minutes. No `kanban.db`: no Hermes, checked again every 5 minutes. A failed poll keeps the last snapshot and reports nothing. Snapshots go to shared `hermes-kanban.boards`, only when they changed.
- **Shape check** (`lib/board.js`): `/board` must have `columns[].tasks[]` with `id`, `title`, `status`, `priority`, `assignee`, plus `assignees` and `now`; anything else shows `Hermes <version> not supported yet`.
- **Changes** (`lib/changes.js`): two boards of the same machine are diffed by `[machine, id]`; no previous board sets the baseline. One change per task: failed (`consecutive_failures` went up, with `last_failure_error`), else needs you (became `blocked` or `review`, or got the warning `block_unblock_cycling`), else done. A task new since the baseline counts as a change from nothing.
- **Unseen and the dot:** per visible machine counts of needs-you and done events, in shared `hermes-kanban.unseen`. The panel marks a machine seen (shared `hermes-kanban.seen`, `Record<machine, at>`) when it shows it with something unseen, which zeroes it; the machines panels show now (shared `hermes-kanban.shown`, one entry per panel copy, renewed every 30 s, stale after 2 minutes) collect nothing.
- **Toasts and sounds:** `notify` with `devbox: writer needs input` / `finished` / `failed` (in single agent mode `devbox needs you`, `devbox: task finished`, `devbox: task failed`), the task title (and the failure) as body, 8 s, and an action `pane.focus` to the last focused Hermes pane of that machine (shared `hermes-kanban.lastPanes`), else its first Hermes pane, else a terminal pane, else any pane there; no action without one. At most one `playSound` per pass, `blocked` before `done`. `setBadge("•")` while a needs-you event is unseen (no number), `null` otherwise, only while `badge` is on, cleared only by the copy that set it.
- **Requests** (`lib/request.js`, `lib/api.js`): `exec("sh", ["-c", REQUEST_SCRIPT, "sh", mode, method, url, body], { on: machine })`. The script picks the key file by mode (`gated`: `~/.hermes/dashboard.token`; `open`: `~/.hermes/webapp/session-token`; `none` for `/api/status`) and runs `{ printf 'Authorization: Bearer '; cat "$key"; } | curl -sS --max-time 15 -X "$method" -w '\n%{http_code}' -H @- … "$url"`, the body as `--data-binary "$4"`. Kanban paths always end in `board=default`; task IDs must match `^[A-Za-z0-9_-]{1,64}$`. Writes: `PATCH /tasks/<id>` (`status`, also `archived`; `assignee`, null sent as `""`; `priority`), `POST /tasks/<id>/comments` with `author: "herdr"`, `POST /tasks`. No `DELETE`.
- **After an action:** the overlay shows the status from Hermes' answer (`outcomeText`), reads the task again and sets shared `hermes-kanban.refresh` `{ machine, at }`, which makes the watcher poll that machine at once.
- **New task:** no pick (and always in single agent mode) sends Hermes' `resolved_default_assignee` from `/orchestration` (its `kanban.default_assignee`, else the active profile), as Hermes' own board does; `None` sends no assignee.
- **Access** (`lib/setup.js`, `access.js`): `/api/status` `auth_required` tells the mode. Open: the web app's token, nothing to set up. Gated: on a 401 or a gateway down, a probe (units `hermes-gateway*.service`, MainPID, `curl --version`, `python3`, key, drop-in, whether `/proc/<pid>/environ` holds the variable) gives the state. **Set up access** shows `SETUP_STEPS`, then on Confirm probes again, checks `/api/status` once more and runs `SETUP_SCRIPT` with the unit as `$1` (checked against `^hermes-gateway[\w.@-]*\.service$` here and in sh): the key only if missing, the drop-in `herdr-kanban-token.conf` atomically with mode 0600, `daemon-reload`. Only the click on **Restart gateway** runs `exec("hermes", ["gateway", "restart"], { on, timeout: 600000 })`; then `/api/status` every 2 s for about 100 s and `/stats` with the key. One restart per machine at a time (shared `hermes-kanban.restarting`). Each flow stays with the machine of its first click.
- **Remove access** (`settings.js`, `nextRemovalStep`): drop-in and `daemon-reload` (`REMOVE_SCRIPT`), then the restart on a click, then the key (`DELETE_TOKEN_SCRIPT`, which exits 3 while the drop-in exists and 4 while the running gateway has the variable).
- **Untrusted text** (`lib/text.js`): titles, bodies, comments and reasons are escaped; only `<br>` and `<a href="https://…">` for bare https URLs are made; `openUrl` opens only `https` and only on a click. No Markdown renderer.
- **Settings** (`lib/settings.js`): one schema (key, type, default, label, about) for `single_agent`, `status.color`, `toast.needs_you`, `toast.done`, `sound.needs_you`, `sound.done`, `badge`, `poll_seconds`, `update_check`; file `appHome()/hermes-kanban.json`, nested or dotted keys, a wrong value means its default; saved with `writeTextFile` against the text read (never over a broken file), then shared `hermes-kanban.config`.
- **Update check** (`lib/update.js`, from ghchecker): the lease holder at most hourly runs a pass; a request to `https://api.github.com/repos/Srv-02/herdr-hermeskanban/releases/latest` only when the last is 24 h old, the installed version (from `mods/hermes-kanban/mod.json`) changed or the clock moved back. Result in shared `hermes-kanban.update` `{ at, local, latest }`.
- **Commands** (`nextCommand`, for keys.json `hermes-kanban:<command>`): `refresh`, `filter` (the second filter row), `settings`, `new`, `open` (the first row).

## Watch out

- The folder name is load-bearing: icons are `mods/hermes-kanban/icons/<name>.svg`, the version is read from `mods/hermes-kanban/mod.json`, overlays open `mod: "hermes-kanban"`, shared keys are `hermes-kanban.*`.
- The key must never be in an argument: `exec` has no stdin, so the header is piped inside the remote `sh` (`printf` is a builtin, `cat` reads the file). Never put the key, or any value, into the script text; values go as positional parameters. Output shown from the machine goes through `redactSecrets`.
- Never restart the gateway without a click, and never delete the key while the drop-in exists or the running gateway has `HERMES_DASHBOARD_SESSION_TOKEN`: Hermes reads the file at import and exits when it is gone.
- Without `?board=default` the API takes the active board, and a board switch in Hermes' web app would redirect the mod.
- Task IDs are unique per board only: key everything by machine and ID, and send every action to the task's machine, never the focused one.
- The first board of a machine is a baseline, not news; else every restart of Herdr, of the gateway or of the lease holder floods toasts.
- A virtual list's rows take no handlers: clicks come by key through `on_item_click`; hover is a style. Each row gets its key as `.id()`, and so does every element with `.hover()` (`npm run lint` checks it): GPUI repaints a hover change only for an element with an identity.
- Each `setShared` re-renders every mod: write only what changed (boards, unseen counts, the shown entry, the seen mark).
- Text from Hermes is untrusted: draw it as escaped plain text, never through a Markdown renderer that may load remote images.
- `exec` stops after 30 s by default; requests get 20 s, the restart 10 minutes.

## Done when

- `herdr-app check ~/.config/herdr-app/mods/hermes-kanban` passes and `herdr-app status` shows `"errors": []`.
- The `Hermes` pill opens the panel; a Hermes pane on `devbox` shows its board at once; a shell pane shows `No Hermes in this pane`; a click into the search keeps the board.
- The board shows Hermes' groups in its order, the highest priority first; Blocked shows its reason, a ready task without an agent `no agent, will not start` when no default is set.
- `Open | Done | All`, two picked agents (`2 agents`) and a search narrow the list; the funnel opens `Prio` and `Group`, and a hidden `P1` puts a grey dot on it.
- A task on `labbox` that becomes blocked while `devbox` is shown gives a toast `labbox: writer needs input`, a red dot on the pill and a strip `labbox needs you`; `Go to pane →` focuses labbox's Hermes pane and clears the dot.
- In the overlay, `Move to` offers only Hermes' moves; a move Hermes redirects says `Hermes moved it to Ready`; `Comment & unblock` on a blocked task with a parent not done keeps the comment and says the task stays blocked; Archive asks first.
- `+` creates a task on the shown instance; without a pick it goes to the default agent, with `None` it stays unassigned.
- On an instance with sign-in, **Set up access** shows the steps, writes the key and the drop-in, and waits at **Restart gateway** without restarting; after the click the board appears.
- **Remove access** goes drop-in, restart on click, then key, and refuses the key while the gateway still uses it.
- Single agent mode on `devbox` hides agent names, the agent filter and the picker there only.
- The gear opens Settings; `Check every` and Save write `poll_seconds` to `hermes-kanban.json`.
- With shared `hermes-kanban.update` naming a newer release, the gear is gold and shines; the dialog shows the gold box.
- A command line on the Hermes machine never shows the key (`ps`), and nothing on the Mac holds it.
