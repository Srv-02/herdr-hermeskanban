# Screenshots

The README images in `screenshots/` and `preview.png` are cards: crops of a running Herdr window, placed on a shared frame and gradient and rendered at 2x with a transparent outside. Everything shown comes from made-up data for two invented machines, `devbox` and `labbox`, never from a real board, machine or account.

## One command

```sh
scripts/screenshots/shoot.sh
```

`scripts/screenshots/shoot.sh board overlay` shoots only the named cards (hero, board, overlay, notifications, settings); `hero` renders `preview.png` at the top of the README, with its feature list as text on the card (`cards/hero.html`, keep it in line with the README intro); `CROP_ONLY=1` re-crops and renders from the raw shots in `tmp/shots-raw` without launching anything.

For each card it prepares a separate Herdr instance at that card's window size, launches it, opens the spaces `labbox` and `devbox`, sets every state through the mod's own commands (`herdr-app do hermes-kanban.open|settings`, the ones `keys.json` can bind), takes the shots, quits and cleans the instance, then crops the shots and renders all cards. Needs macOS with a Retina display, Herdr.app, Microsoft Edge (headless, no window), `node` and `sips`. Look at every image before you commit it: no user name, no real path, no real host, no real machine.

What it never does: touch your own Herdr or its installed mod, reach a machine, run Hermes or `curl`, ask GitHub, use mouse or keyboard automation, or raise a window. The one focus change is macOS giving a new app instance the focus when it launches. The window must stay visible: Herdr draws nothing new in a minimized or fully covered window, and the shots would show an old frame.

## Files

- `shoot.sh`: the whole run (prepare, launch, drive, shoot, quit, clean, crop, render). Sizes as in GitHub Checker: `preview.png` 2044 x 1144, and every feature card as wide (2044 px), its panel, overlay or dialog centered at its own size. Each window is 860 points wide at 2x (panel 446 points, app zoom 1); its height is set per card (`H_*` in `shoot.sh`) so the panel shows its rows down to its status bar. The board card shows the whole panel; the overlay card the task overlay down to its comment box; the notifications card the panel with the strip `labbox needs you`, the `Hermes` button with its dot and the toast (`TOAST_BOX` and `BUTTON_BOX` in `shoot.sh`); the settings card the dialog. When the fake data or the mod's rows change, adjust `H_*` (one row is 46 points, a group heading 32) and look at every card again.
- `demo-instance.sh`: `prepare | start | space | turn | quit | clean` for the separate instance. Its `HERDR_APP_HOME` is `tmp/shots-home` and its core session `hkshots`. It deletes only fixed paths below `tmp/` and the core state `~/.local/state/herdr-core/hkshots`, and refuses anything else; `quit` kills the instance by its PID (matched on its own `HERDR_APP_HOME`) when it does not quit. `prepare` creates the demo folders below `tmp/shots-spaces`, copies the mod of this checkout, patches that copy with `demo-hook.mjs`, and writes a layout with the panel shown and the `Hermes` button in the tab bar. It also marks the welcome screen and the what's-new window as done, so no popup needs a click, and the update check as done today (up to date; `DEMO_UPDATE=1` makes a release 1.1.0 available, for the gold gear and box, never for the README). `DEMO_SCENE` picks the fake board (`board`, `overlay`, `notifications`); `turn` makes a task on `labbox` need input.
- `demo-hook.mjs`: patches the instance's copy of the mod (never `mods/hermes-kanban`, never your installed mod): every `exec` the mod runs on a machine goes to `demo/hermes.mjs`, run on this computer; the spaces named `devbox` and `labbox` count as those machines, with Hermes in their terminals; the update check asks GitHub nothing. It stops loudly when an anchor in the mod has moved; `test/screenshot-hook.test.js` applies it to the current mod on every `npm test`, checks that the fake answers every call the mod makes, and that the shipped mod has no trace of it.
- `demo/hermes.mjs`: the fake Hermes. It answers the Kanban API (`/board`, `/workflow`, `/orchestration`, `/diagnostics`, `/tasks/<id>`, `/api/status`), the stamp, the probe, the access scripts and the gateway restart, with made-up tasks such as `Draft release notes for v2.4` for the agents `writer`, `coder` and `research`, with times relative to now. Writes such as a move, a comment or a new task answer as Hermes does and change nothing.
- `render.sh`: renders a card into a PNG with headless Microsoft Edge (`EDGE=/path/to/browser` picks another Chromium-based browser).
- `cards/card.css`, `cards/*.html`: the shared frame and one card per image. The crops (`cards/*.png`) are ignored by git and the browser profile lives in `tmp/edge-profile`: they hold window content, only the finished card goes into `screenshots/`.
